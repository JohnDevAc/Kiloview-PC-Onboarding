# PC Agent 0.7.4 / 0.7.4-dev.1 release candidate

Server-local onboarding now restores both NDI settings files and Agent state when configuration, membership completion or cooperative cancellation fails. The configuration lease stays held until recovery finishes. Recovery attempts every affected file and reports incomplete restoration. The normal Agent validation command selects an interface accepted by production identity validation, retaining APIPA rejection.

The local schema-1 process contract, installed/elevated checks, prior license requirement and remote Yes/No/UAC flow are unchanged. Recovery covers configuration files; it does not reverse independent package/startup/firewall refresh or provide forced-termination/power-loss durability.

Software upgrades through server-command install and configured standalone Setup preserve saved Agent identity, address, memberships and multicast state. A temporary APIPA address cannot replace the saved address; the running Agent continues to wait for a usable address on its saved adapter. A missing/ambiguous adapter or invalid/unreadable saved state fails before package, startup, firewall or process changes. New unconfigured installation does not select an adapter. Explicit onboarding keeps its configuration-writing path, guarded against invalid network identity before installation mutations.

Setup validation passes 27 labelled checks and Agent validation passes 22, including six isolated local-transaction scenarios and five upgrade validation groups. The original sole-address selection failed the APIPA fixture before correction. Partner checks passed: 26 server regressions, 13 frontend checks, installer helpers, three native lifecycle checks, 12 interoperability scenarios and diagnostic HTTP. Live update-feed/download tests were disabled. Installed elevated execution, alternate-account UAC and physical-network acceptance remain separate.
